## Decisions where the task was open

* The checks run in `pytest_collection_modifyitems` (tryfirst) and raise `pytest.UsageError`: the session ends with exit code 4
  and the message, before any test runs.
* Only the files collected in the session are scanned, so a baseline line is stale only if its file was scanned and the violation
  is gone, or its file no longer exists, or it is an H6 line. A run of one file does not report the rest of the baseline.
* H1 treats `import test_x` / `from tests.test_x import` / relative imports as test-module imports only when a `test_x.py` exists
  below `tests/` (the T00 test imports `tools/test_report.py`, which is a tool, not a test module).
* H2 also flags `<alias>.<_name>` reads where the alias is a product module, and `setattr/getattr/patch(...)` with a private
  target given as a string. `_asdict`-style namedtuple methods and dunder names are allowed. One H2 line per file (test empty).
* H3 also matches test names with `_` read as a space, so `test_issue_99_fix` says "issue 99". Only test names and test docstrings
  are checked, as the task says (not module docstrings).
* H4 is a static check: each `parametrize` needs `ids=` or every value a `pytest.param(..., id=)` (lists, comprehensions, `+`,
  and module-level names are followed). `@pytest.fixture(params=...)` is held to the same rule.
* H5: "one sentence" is the first paragraph of the docstring (up to the first blank line) ending in `.`, `?` or `!` with no sentence
  break inside; backticked text and `e.g.`, `i.e.`, `etc.` are ignored.
* H6: the folder must be `issueNNN` or `jobNN`; the README `ref:` must be a file that exists, belongs to that folder, is not under
  `_issues/_closed/` or `.agents/jobs/_complete/`, and (for a job) whose `NN-*-progress.md` does not say `Status: Closed`.
  `kind` must be `guard` or `report`. A `report` folder is skipped at collection (`pytest_ignore_collect`) unless a command-line
  argument is that folder or a path below it.
* `--write-baseline` was a temporary `__main__` block of `hygiene.py` (it refused to run while the file existed). I ran it once and
  deleted the block; the file is not in the module now.
* The new files are free of violations themselves (not in the baseline). The one process-starting test pair in
  `test_hygiene.py` will be `process` tier in T02.
