## Decisions where the task was open (please review)

1. **A "real junction" does not make a test `process`.** `FakeSystem` creates its links as real NTFS junctions inside
   `tmp_path`, in-process (`_winapi`/`ctypes`, no child process). Reading the task's wording literally would put the whole
   engine, catalog and distribution suites into `process`. I used: `process` when the test uses `WindowsSystem` or anything
   that H9 shows starting a process, a loopback server or a registry key/shortcut under a test name (the old
   `windows_integration` tests became `process`). Tests that only use `FakeSystem` stay `unit`. If the owner wants
   `FakeSystem` junctions counted, the number of `process` tests grows by several hundred.
2. **The tier of a test is the one on the nearest node that has a tier mark** (the test or a parameter set, then its
   class, then its module). `-m unit` must not select a `process` test of a `unit` module, but pytest's `-m` sees the marks of
   all parents; so the plugin hides the farther tier mark from `-m` for such tests (`_hide_tier_marks`, an instance-level
   override of `iter_markers_with_node`). Without it `-m unit` and `-m process` would both select the exception. Shown by
   `test_every_test_needs_exactly_one_tier_and_the_nearest_mark_decides`.
3. **H8** counts "exactly one tier" at the nearest node: none, or two different tier marks at that node, is a violation
   `H8|file|test` (also for `tests/_temp/`). No existing test violates it, so the baseline has no H8 line.
4. **H9** is enforced while a `unit` test runs (setup, call, teardown): `subprocess.Popen.__init__` (so `run`, `check_output`,
   `from subprocess import Popen`, asyncio subprocesses), `os.system`, `socket.socket.connect` and `connect_ex`, and
   `time.sleep` over 0.01 s raise `pytest.fail` (a `BaseException`, so product code with `except Exception` cannot swallow
   it). The one `connect` made by `socket.socketpair` (asyncio's own self-pipe on Windows, `_fallback_socketpair` on
   3.14) is allowed: it reaches no other program. A violation raised in a thread or lost inside an asyncio task still fails
   the test with the H9 message (found by `test_ui_unowned_file`, which otherwise failed with a 25 s timeout). A test
   that mocks any of these itself keeps its mock (the guard is installed first).
5. **Baseline for H9**: `H9|file|test` lines for `unit` tests that still break the rule. Such a test passes while it breaks
   it (the guard only notes), and fails in teardown with "the baseline line ... no longer matches a violation" once it
   stops breaking the rule, so the baseline only shrinks (like T01's static lines). T01's lines are untouched; the header
   now says H1-H9. Only two tests went into the baseline: they sleep in real time by design and no tier fits them better
   (`test_engine_locks::test_racing_runs_never_hold_the_lock_together`, threads sleeping 0.02 s;
   `test_record_http_fixtures::test_a_failing_run_leaves_the_case_file_untouched`, 7 s of real retry delay). All other
   violators were moved to `process`, because there the real process, server or worker is the behaviour (or at least the
   way the test is written today; later area tasks may bring them back to `unit` with fakes).
6. **`scripts\test.cmd`**: first argument `--process` or `--all`, everything else goes to pytest. `--all` passes no `-m`
   (H8 guarantees every test has a tier). The last line printed is `[scripts] Tiers run: unit | unit, process | unit,
   process, release`. A pytest `-m` given by the user after the tier option wins over the script's, and the last line would
   then be wrong (a small known limit, not documented in the script).
7. **`windows_integration`** replaced by `process` in tests, `pytest.ini`, `_docs/development_guide.md` and
   `_docs/rehaul_design.md`. It remains in history records that I must not rewrite or may not edit: closed issues,
   completed job logs, job 09 files, T02's own task file, and `_issues/issue036-test-suite-quality.md` line 54 (the finding
   that describes the old state). So `git grep -n windows_integration` is not empty: see the output below.
