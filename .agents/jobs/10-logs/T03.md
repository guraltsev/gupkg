## Decision to flag: the registry tool cannot take an injected `sleep`

`gupkg_registry.cli.main` and `update_registry` build `HttpClient(scope.system, cache_dir=..., env=...)` in
`src/gupkg_registry/update.py:_client` with no `sleep`, and the client's default is `sleep=time.sleep`, bound when the
class is defined, so patching `time.sleep` does not reach it. The brief says to stop and ask for a product change. I did
not need one: the three registry tool tests fail the package only incidentally, and the 7 s came from a vendor page that
the fake machine did not serve (`UnexpectedCall`, an `OSError`, which the client retries after 1, 2 and 4 s). The tests
now serve that page with status 404, a permanent failure the client does not retry (`_RETRY_STATUSES` is 429, 500, 502,
503, 504). The assertions are unchanged (exit status 1, outcome list, the staging folders, the warning). If the owner
wants the retry itself exercised through the registry tool, the product change is a `sleep` parameter on
`update_registry` and `main` passed to `HttpClient`; the HTTP client's retry delays are already tested in
`test_http_client.py` with an injected `sleep`.

`tools/record_http_fixtures.record_case` calls `HttpClient(..., sleep=time.sleep)`, which looks `time.sleep` up at call
time, so that test patches `time.sleep` (the clock is a real boundary, `tests.md` 4.5) and now also asserts that the
failed request was retried (`waits` is not empty), which keeps the scenario exact.

## Inconsistencies found (rule 13), not fixed

- `tests/test_registry_validate.py` still imports private `_stray_problems` (baseline `H2`); the policy forbids it.
- `update_registry` and `main` of the registry tool offer no `sleep`, while `EngineContext` does (`context.py:105`), so
  a registry tool test cannot observe its retries.
- `src/gupkg/services/http.py` binds `sleep=time.sleep` at definition time, so no test can redirect it by patching
  `time.sleep`; this is why the H9 guard "does not see" the HTTP client's sleep (`tests.md` section 5 mentions imported
  names). The guard cannot find the next instance of this pattern; a `sleep=None` default resolved at call time would.
- The tests in `tests/test_fingerprint.py` and `tests/_conditional/old_registry_layout/` still copy the whole snapshot
  (1.4 to 1.8 s each, unit tier): same decision 3 pattern as the validate tests.
