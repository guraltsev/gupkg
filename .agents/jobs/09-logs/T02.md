Source files changed: `model/manifest.py`, `model/template.py`, `engine/{portable,appbuild,lifecycle,executor,planner,effects,health,

Design points that the task left open and that I decided (report them if wrong):

- `MODES` of `manifest.py` is now `("system", "user")`; `PORTABLE = "portable"` is a separate constant. `Manifest.is_portable` and
  `Manifest.supports(mode)` (a portable package supports `user` only) are new; `check_supported` takes the raw `modes` of the package.
- The hand-over runs when the chosen manifest has `[portable]` (`executor._activate`), the plan line likewise (`planner`), the
  fingerprint skip of persisted items likewise (`health`).
- `ModeContext.integrate` is now `full` or `none` (it was `user` or `none`); only user mode can be `none`. `[integration.user]
  integrate = "full" | "none"` is the new key; the settings `SCHEMA` stays 3 (T04 owns the schema).
- `state.py` `MODES` is `("system", "user")`: an install record or ad-hoc entry that says `portable` is now a record problem.
- `--in-place` stays (it is the ad-hoc root of a distribution folder, not the portable in-place of D42).
- The registry fixture has no `<name>-portable` copy: no test needs one (all portable fixtures are the three portable-only packages).
