## Decisions

- **Effect kind `location_file` (new), not `file`.** `file` is a content wrapper confined to the mode's `bin` folder and is removed
  unconditionally. `gupkg-location` lives in the root's data folder and must be removed only while its first line still holds the value
  gupkg wrote (a person may edit it, issue 035 §4.9). So the kind has its own confinement (`root_data`), its own remove rule and its own
  verify rule (first line compared, not a hash, so a harmless line-ending change is not drift). It replaces the `forwarder` kind. An
  install record written before T11 that still holds `forwarder` effects fails with "unknown effect kind" on removal (no migration code, D54).
- **No manifest table.** `[root_forwarder]` is removed; the effect is built for the package named `gupkg` when the context has a root
  data folder (the same "only gupkg" rule the table had, now in the engine).
- **Heal path removed.** The old template repaired a broken forwarder from the newest `<root>\gupkg\<version>\gupkg`. It existed only
  to serve the forwarder (`GUPKG_BROKEN`), is not in the new order (bundled, location, PATH), and went with it. Its three tests are gone.
- **`gupkg-location` hardening found by test.** The first version of the template ran a command written in the file (a `&` in an
  unquoted `echo` of the skip line). `test_gupkg_location_is_read_as_data_and_never_executed` failed (marker file created); the template now
  refuses a first line with `& | < > ^` and never echoes it.
- **Elevated PATH step.** `where "$PATH:gupkg.*"` (PATH only, never the current directory). The launcher's own folders are checked once first
  (failure refuses the run); each candidate is then checked on its own and skipped, with a `Skipped PATH entry <folder>` line, when it fails.
  New kind `s:` in the fixed PowerShell check: shim, `<name>.config.toml`, the `target` the config names, the target's parent through
  `v:` (junction rule) and the target's folder recursively.
