## Decisions the task did not spell out

- `Scope` gained an optional field `system` (not part of equality or repr). `Scope.require_trusted(path, what)` needs the
  machine boundary to judge a folder, and the task gives the method no `system` argument, so the scope carries it
  (`build_scope` and `make_scope(..., system=)` set it). A system-mode scope without a `system` refuses every location
  (fail closed). In user mode `require_trusted` does nothing.
- Functions that only had `system` to ask "am I elevated" now take the `Scope` (so the check is `scope.mode`):
  `services/hooks.py` (`require_trusted_code`, `load_hook`, `HookContext.scope`), `services/gitenv.py`, `services/registrysource.py`,
  `catalog/registry.py` (`cache_state`, `load_registry`, `sync_registry`), `services/http.github_environment`, `unpack_git`,
  `checkout_commit`, `fetch_git`, `populate_git`, `TrackEnvironment.scope`, `engine/locks.package_lock(scope=)`.
  `safe_process_environment(extra, *, system, mode)` takes the mode (port.py cannot import `Scope`).
  Those that also run processes use `scope.system` for that.
- `require_admin_only` (port.py) was only used by the places above and is deleted.
- `gupkg.scope.process_mode(system)` is the one place that calls `is_elevated_run`; `build_scope`, the `tui`/`manager`
  forwarder check in `cli.py` and `gupkg_ui/startup.py` call `process_mode`, not `is_elevated_run` (the task's grep lists
  only scope.py, elevation.py, the System implementations, bootstrap.py; `port.py` holds the definition).
- `gupkg_registry/update.py` (the maintainer tool, in this repository's `src`) builds a scope for its own token with
  `make_scope(process_mode(system), root, "gupkg-registry", default settings, {}, system=system)`.
- `verify_each` / `verify_effects` / `diagnose` lost their `elevated` parameter. Consequence: a recorded `env`/`path` effect whose own
  `scope` is `user` is now read from the user environment even in a system-mode run (before: reported "unverified"). A system-mode
  record cannot hold one (the catalog flags a record of another mode), so this only matters for a corrupt record. Open question below.
- `unsafe_relaunch_argument` is renamed `unsafe_launcher_argument` (and `UNSAFE_RELAUNCH_CHARACTERS` to
  `UNSAFE_LAUNCHER_CHARACTERS`) in `system/port.py`; it is called only by `gupkg_ui/client.py` `refuse_unsafe`.
- The one exception class is `gupkg.selfmgmt.elevation.UntrustedLocationError` (catalog's `UntrustedLocation` is gone). A lock
  folder that is not admin-only now raises it (was `PackageBusy`, which reported "locked"); the error code is `untrusted-location`.
- `selfmgmt/elevation.py` `enforce_bundled_runtime` keeps its own `elevated` argument (bootstrap calls it before any scope exists).
- `check-updates` always writes the root (`writes_root` is deleted with the "report only" branch of the engine and the planner).

## Document changes (the content of the API-2 contract)

Every document and every event record: `"api": 2` (`report/events.py` `API_VERSION`). `gupkg_ui/client.py` accepts only `"api": 2`.

Removed:

- Lifecycle result documents (`install`, `update`, `switch`, `uninstall`, `check`, `cleanup`, `check-updates`, `link`): `relaunched`,
  `child_exit_code`, `child_raw_exit_code`; the call-level error `child-no-result`; the per-target error code `mixed-modes` and the
  status `not-run` (they existed only for the relaunch). The `BatchResult` document of the engine lost the same fields.
- `--plan --json`: `requires_elevation` in each `plan` (it only existed for the relaunch; a plan carries `mode`). The human plan text no
  longer says "needs administrator rights". The `check-updates` plan lost its `writes` key (a run always writes; `download` stays).
- `check-updates` result `details`: `written` (always true now; `populated`, `found`, `path`, `notes` stay).
- The UI program's own batch document (`gupkg_ui/console.py` `outcome_document`): `relaunched`.

Kept: per-target `mode` in plan and result documents, and `root_cleanup` of a root-wide `cleanup` (keyed by the run's one mode).

Recorded by T06 and unchanged here: `list`, `list --names`, `info`, `search` `--json` carry document-level `mode` and `root` after
`exit_code`; rows lose `mode` and gain `restriction` and `restriction_reason`.

Internal (not a document): `gupkg_ui.client.CallResult` lost `child` and `relaunched`; `entries()` and `errors()` read the call's own
document only.
