## Plan

(4) tests: converted or deleted.

Design decisions (the task did not say):

- `Mode` is a `StrEnum` (`"user"`, `"system"`): a mode compares equal to its name, prints as it and goes into JSON as a
  string, so records, documents and `PackageResult.mode` do not change.
- `Scope` also has a `requires_elevation` property (mode is system) and `describe()` (`<mode> root <path> (<source>)`).
  The property is only there because `relaunch.py` (T07) still reads it.
- `gupkg.scope.build_scope_and_layers` returns the scope and the `LayerReport`s (needed by `gupkg settings path` and the
  run log); `build_scope` is the same without the reports.
- `Catalog.from_scope(scope, ...)` is a bridge: the catalog of one scope reads the scope's root (so `--root` is seen).
  `from_settings` stays for T06 to remove with the rest of the multi-root scanning.
- `Selector.mode` and `_MODE_PREFIX` are gone from the catalog; a `system:`/`user:` prefix is refused by `parse_selector`
  (`CatalogError`) and by the CLI at start (usage error, exit code 2).
- `modes.py` is replaced by `targets.py` (`resolve_target`, `ResolvedTarget`, `TargetRequest`; 191 lines).
- Run log: the Resolve phase has a step `<mode> root <path> (<source>)` in every plan; the executor emits it as a step event,
  so the run log keeps it. The `RunStart` event (machine contract) is unchanged.
