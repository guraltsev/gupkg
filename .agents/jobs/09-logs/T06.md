## What was done (design decisions the task did not spell out)

- `Catalog(scope, system, verify_effects=False)`. `Catalog.from_settings`, `Catalog.from_scope`, `_from_roots` are gone; the
  registries come from `scope.settings`; the root is `Catalog.root` (`Root(scope.root)`). `resolve_package_path` is deleted
  (it had no caller in `src`; it needs a scope now).
- `Root` keeps only `path`. `PackageView.root` is `None` for an `available` view (as before) and `Root(scope.root)` for a local one.
- A path outside the root: `Catalog._resolve_path` raises `NotFound("<path> is not inside this scope's root (<root>)")`.
  A distribution folder (a version directory with a `pkg.toml`) is read through the new `Catalog.resolve_distribution(folder)`,
  which `targets.resolve_target` calls for a path outside the root in a normal run. An elevated run does not read it (as before).
  A package root or `current` outside the root is no longer copied in: it is `NotFound` (before, it became an ad-hoc root and
  `_copy_source` copied its version).
- Identity, not spelling: a package folder inside the root that is a junction to a folder outside it lies outside the root
  (the 0.17 "a junction still resolves for an explicit path" behaviour is gone; tests changed accordingly).
- Kept, because they are the elevated-run trust rules (D31) and not multi-root machinery: a system-mode catalog skips a root that
  users can modify (`Skipped <root> in an elevated run: <reason>` warning, nothing listed, no cache read; one cached
  `directory_untrusted_reason` call), and `_resolve_path` refuses an untrusted package folder (`UntrustedLocation`). These replace
  `_trusted_roots` and `_require_system_path` with no root list.
- `_view`: record `mode` other than `scope.mode` is `the install record says <mode>; this package was moved between scopes — reinstall it`;
  a package with a `current` entry (any status but absent) and no readable record and no record problem is
  `no install record (made by an older gupkg); reinstall with: gupkg install <name> --force`. The catalog writes nothing.
- `_verify`: the `Mode` of an `env`/`PATH` effect is `scope.mode`; the effect's own `scope` field is no longer read.
- Q14: `PackageView.restriction` (`system only` / `user only`) and `restriction_reason` (the refusal text of `check_supported`
  for the newest pinned version of the entry; `command="install"`). Only `Catalog.list(include_available=True)` sets them.
  `manifest_modes(path)` moved from `targets.py` to `catalog.py` (public) so both use it.
- `health.diagnose(... shadowing=...)` lost its parameter and `_shadow_notes` (the grep of the task covers `shadowing`);
  `install_notes` takes the mode from the install record (`record.mode == "user"` for the "self-reported" note), because `PackageView.mode` is gone.
- `Request.in_place`, `TargetRequest.in_place`, `lifecycle.install(in_place=)`, the `--in-place` option and the CLI forwarding
  of it are removed; `_copy_source(folder)` has no `--in-place` branch.
- `list`, `info`, `search` (`--json`) carry `mode` and `root` once; `viewdata.package_data` has no `mode` and gains
  `restriction` and `restriction_reason`; human `list` has no mode column, marks `(system only)` / `(user only)` and prints
  `reason: <text>`; human `info` has no mode. `gupkg_ui.plans.read_packages` takes the mode from the document (no mode: no rows).
