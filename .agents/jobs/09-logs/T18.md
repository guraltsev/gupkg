# T18 log: `gupkg.cmd` forwards its arguments unchanged

Branch `i035/T18` (from main 442daf6). Uncommitted at the time of writing: only this log.

## Reproduction (before; main 442daf6)

Harness: real `cmd.exe`, a copy of the launchers beside the real bundled `python\python.exe` (junction), a stub `bootstrap.py`
that prints `json.dumps(sys.argv[1:])`; the raw text after the launcher name is what a person types. `inner` is
`src\gupkg\gupkg.cmd`, `outer` is `src\gupkg.cmd` (the target of the shims; it does `call` inner).

```
inner and outer, identical:
--overwrite=a,b      -> ['--overwrite', 'a', 'b']
--skip-checksum=cli  -> ['--skip-checksum', 'cli']
--x=1;2              -> ['--x', '1', '2']
""                   -> []                      (an empty argument vanishes)
"--root=C:\a b\c", "a b  c", "C:\dir\\", café-жук, 100 x, -- target, list a b -> unchanged (OK)
```

Hostile arguments, today (canary = file that `copy nul <path>` creates; `rc` is the exit code):

```
"a&b"                      -> argv []                 (the & ran: `b""` is a command)
"a&copy nul %CANARY%"      -> CANARY CREATED          (injection through the quoted argument)
"a|b"                      -> rc 255, 'b""' is not recognized
"a|copy nul %CANARY%"      -> CANARY CREATED
"a>b" / "a>%CANARY%"       -> argv [] / CANARY CREATED (redirection ran)
a^b                        -> ['ab']                  (the caller's own cmd strips the caret)
"%PATH%" / !VAR! / "a""b"  -> expanded by the caller / '!VAR!' / 'a"b'
"a&copy nul %CANARY%  (unbalanced quote) -> CANARY CREATED
"a^&copy nul %CANARY%" (outer)           -> CANARY CREATED
a^&copy nul %CANARY% (outer)             -> CANARY CREATED (call parses the arguments a second time)
"%%PATH%%" (outer)         -> %PATH% is expanded twice (call)
"a^&..." (outer)           -> the quoted caret arrives doubled (a^^&)
```

So today's `gupkg.cmd` is injectable through any quoted argument (the loop writes `"%~1"` inside `set "..."`, whose own
quotes then end early). The rebuild loop is the cause of both the splitting and the injection.

## The native shim (the reason the loop exists)

The loop comment says `cmd.exe /c quoting can leave a leading quote on forwarded arguments when this launcher is started by the
native shim`. Reproduced with a probe (the shim copied to `g.exe`, `g.config.toml` with `forward_arguments = true`):

- the shim always starts its target as a command line of fully quoted arguments (`"<target>" "list" "a" "b"`);
- for an `.exe` target that is exact: a probe target printing `GetCommandLineW()` got
  `"--overwrite=a,b" "a b" "a&b" "a^b" "C:\x y\\" ""` for the raw arguments `--overwrite=a,b "a b" "a&b" a^^b "C:\x y\\" ""`
  (so the existing `test_launcher.py` stand-in `python.exe` shims see the right arguments);
- for a `.cmd` target the shim runs `cmd /c "<target>" "list" "a" "b"`; `cmd` strips the first and the last quote of the whole
  line and fails before the batch file starts:

```
> g.exe list a b            (target = ...\App\gupkg.cmd, also ...\App\gupkg\gupkg.cmd)
'C:\...\App\gupkg.cmd" "list" "a" "b' is not recognized as an internal or external command,
rc=1
> g.exe                      -> works (no arguments, no extra quotes)
```

This is the same failure issue 035 section 11 item 1 reports for the installed `C:\opt\gupkg\current\App\gupkg.cmd`.
**No content of any `.cmd` can fix it** (cmd fails to find the command), so the `%~1` loop never helped the shim path: its
comment describes a symptom that is in fact this earlier failure. Fixing it needs a change that is not in this task (see
"Shim: options" below). Manual entry `035-T18-1` records it.

## After (new code)

Same harness, `inner` and `outer`: every row of the cases list is OK:

```
--overwrite=a,b -> ['--overwrite=a,b']      --skip-checksum=cli -> ['--skip-checksum=cli']   --x=1;2 -> ['--x=1;2']
"" -> ['']   "--root=C:\a b\c" -> ['--root=C:\a b\c']   "a b  c"   "C:\dir\\" -> ['C:\dir\']   café-жук   100 x   -- target   list a b
```

Hostile, new (canary never created for any quoted argument):

```
"a&b" -> ['a&b']      "a|b" -> ['a|b']      "a>b" -> ['a>b']      "a&copy nul %CANARY%" -> literal, canary no
"a|copy nul ..." -> literal, canary no      "a>%CANARY%" -> literal, canary no      "%PATH%" -> expanded by the caller (as before)
!VAR! -> '!VAR!'      "a""b" -> 'a"b'      "a^b" -> 'a^b' (test quoted-caret; unquoted a^b is still 'ab', the caller strips it)
"a&copy nul %CANARY%  (unbalanced) -> literal, canary no     "a^&copy nul %CANARY%" -> literal, canary no
```

What is **not** better, said plainly:

- An *unquoted* metacharacter belongs to the caller's own command line (`gupkg a&copy nul x` runs `copy` in the caller's
  shell before gupkg is involved): canary created, before and after, nothing the launcher can do.
- A caret-escaped metacharacter (`a^&copy nul %CANARY%`): the caller's `cmd` removes the caret, the batch `%*` is then
  parsed once more where the `&` is live. Before: created on the outer launcher (through `call`), not created on the inner
  one (the loop happened to break it differently); after: created on both. `a^^^&copy ...` (three carets) is created on the
  outer one now (two batch layers each consume one escape level) and was not before (it errored out). This is the known `%*`
  limit of every batch file; to be exploited it needs a person to type carets in their own shell. Programs never pass such
  characters: `system/port.py` `unsafe_launcher_argument` refuses `& | < > ^ " % !` and control characters before any `.cmd`
  launcher is started.
- `%%NAME%%` through the outer launcher is no longer expanded twice.

## Shim: options (not done: the shim binaries must not change)

The shim path with arguments cannot work for a `.cmd` target. Options:
1. Rebuild the shim so that a `.cmd`/`.bat` target is started as `cmd /d /s /c ""<target>" args"` (an extra outer quote pair).
   The right fix; needs the shim source (not in this repository: only the binaries) and new committed binaries.
2. Make the gupkg shims target the bundled interpreter directly: `target = $App\gupkg\python\python.exe` with the fixed
   arguments `-I -s -B -S $App\gupkg\bootstrap.py` (`--gupkg-program=manager` for `gupkg-manager`). The shim starts an `.exe`
   without a shell, so every argument arrives exactly, nothing is injectable, and no binary changes. Costs: `pkg.toml`'s shim
   tables change, the elevated package launcher's step-3 check (`package-launcher.cmd`, the part that follows a `gupkg.exe`
   shim's config to "that target's gupkg tree") and `launchers_find_gupkg` assume a `gupkg.cmd` target, so both need
   changing (T11 area) and re-testing, and `self repair` must rewrite the shims of installed roots.
3. Leave it: call `gupkg.cmd` (or run `gupkg` from the `App` folder) instead of the shim; the shim works without arguments only.
