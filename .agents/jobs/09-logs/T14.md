## Review round 1 (blocking performance fix and minors)

Performance. Before: `Catalog.installed_effects()` called `list()` (full scan, version scan, registry join) once per `plan_install` and once per `check` target. Now:
- `installed_effects()` lists the root and reads only the install records (`catalog._record_effects`: two lstat for the link checks, a parse cache keyed by file id, size and mtime; a record that is a link is still never read); `scan_root` takes a one-stat shortcut for a folder that holds an install record.
- One `_RootNames` per command call, shared by all targets (`_share_names`), holds a `NameIndex` (planner.py). After each target it re-reads that one package's record (`reload`), so a batch scans the root once. `check` of N packages scans once.
- Pinned by counters, not time: `test_check_of_many_packages_reads_the_records_once` (12 packages) and `test_a_batch_install_of_many_packages_reads_the_records_once` count calls of `Catalog.installed_effects`. Without the fix: 12 and 24 scans; with it: 1 and 1.
- 60 packages on a FakeSystem root (script: install 60 one by one, then check all 60 in one call; same script for both; three runs each):
  - main:   install 1.85-1.93 s, check 0.95-0.97 s
  - branch before this round: install 2.9 s (1.57x), check 0.72 s  (the reviewer measured 8.17 s / 7.48 s on the first version)
  - branch now: install 2.44-2.50 s (about 1.3x), check 0.67-0.75 s (faster than main)
  The remaining install cost is inherent: each install command lists the root and reads each package's record once (about 10 ms for 60 packages; the 60 sequential in-process commands multiply it).

### Rule 7: files that no package owns

Today: `apply_effect` writes a shim, wrapper or shortcut over whatever is at that path, whether or not an install record claims it (a file left by a hand install, another tool, or a package whose record was lost). Nothing is asked or reported, and uninstall later removes it because the record names it. This task does not change that.
A follow-up could: (a) refuse to replace a file with different content that no record owns (the message names the path and tells the user to move it); (b) ask first (`--yes` answers); (c) warn and adopt it through the `adopted` flag of `Effect`, so that uninstall leaves it alone. Open question for the owner, not blocking.

### Known limits (left as they are)
- Fail open: a garbled or unreadable install record of another package provides no names in the ownership view (`check` and `list` report that record). An untrusted root in an elevated run is not read at all (`installed_effects` returns nothing), like the rest of the catalog.
- Rule 5 is met only partly by design: no new keys; the package is `outdated` and the reason is the failure of the update or check-updates, not a field of `list --json`.
- The 80-column clipping of the last character of a wrapped run-log line is pre-existing.

### Inconsistencies found
- `catalog.py` tells a package without an install record to run `gupkg install <name> --force`; `install` has no `--force` option (the `_docs` talk about it too, D54).
